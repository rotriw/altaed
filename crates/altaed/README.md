# altaed 文档增量

此文件保留早期迭代记录。当前已经整理为根 Cargo workspace，构建与目录结构以仓库根 README.md 和 docs/monorepo.md 为准；旧验收日志只在本地保留。

当前已实现原生多文档编辑、新建／打开、保存／另存为、关闭选择，以及正常退出后的会话草稿恢复。每份代码有独立标识与附属数据，沿用真实 Zed Editor；模拟 LSP 不作为默认功能。

当前机器可构建：

```sh
CARGO_TARGET_DIR=.cache/editor-baseline-host/target cargo +1.93 build --manifest-path Cargo.toml --locked --offline
```

新的工作环境先准备固定版本源码与消费者，避免依赖原 Zed 工作区改动：

```sh
python3 scripts/prepare_app.py --source /path/to/zed
# 对输出的 Cargo.toml 使用 cargo +1.93 build --manifest-path ... --locked
```

当前开发机运行 `scripts/run_altaed.sh`，或打开 `target/Altaed.app`；两者默认使用同一个仓库内测试会话目录，避免重启切换草稿位置。

直接运行二进制时，默认会话目录为 macOS 的 `~/Library/Application Support/altaed`，可通过 `ALTAED_DATA_DIR` 覆盖。本次测试窗口使用仓库内 `.cache/ide-session`。源码旁 `.altaed/<完整文件名>.json` 保存版本化附属记录；整目录移动后重新打开会恢复关联。

保存前写入 `.pending` 恢复记录，源码和附属记录全部写入成功后清理。重新打开有 pending 的文件会恢复未完成的保存内容，由用户重新保存；未知格式拒绝读取。此版本仍在开发，不支持多实例共同写同一会话目录。

## 人工验收

1. Cmd-N 新建文档，输入代码；Cmd-S 选择任意文件名保存。
2. Shift-Cmd-S 另存为，得到独立标签；修改其中一个，确认另一个内容不变。
3. Cmd-O 打开已有源码；点击标签切换。
4. Cmd-W 关闭未保存文档，检查保存／保留草稿／丢弃／取消。
5. Cmd-Q 退出，使用同一个 `ALTAED_DATA_DIR` 重启，检查未保存内容恢复、丢弃内容不恢复。

目前支持题目信息查看、测试数据原地编辑、C++ 编译与测试；独立附属信息和目录迁移通过存储测试验证。改名、导出、定期崩溃恢复、外部文件变化协调、提交功能仍待后续增量实现；真实 C++ LSP 已接入，范围见下方 LSP 记录。完整应用目前只验证 macOS；Windows 兼容性准备与验证边界见 `docs/windows-build.md`。

## C++ 运行与测试增量（2026-11-02）

- “运行”菜单提供只编译（Shift-Cmd-B）、全部测试（Cmd-R）、新终端交互运行（Shift-Cmd-R）、取消及当前文档运行配置。
- 新文档默认使用编译器语言模式和 `-O2`；欢迎页检测版本与可用标准，软件设置可选择新文档默认标准，文档运行配置可单独覆盖。已有文档保留自己的参数。编译器从 PATH 发现，也可在配置中指定；参数每行一个，无 shell 展开。工作目录默认源码目录；未命名文档默认应用工作目录，可配置。
- 每次使用当前代码、配置、测试的副本，保存在会话目录的 `runs/<UUID>/`。未保存源码可以编译，不覆盖磁盘源码；不同执行的产物互不覆盖。当前版本保留执行目录，尚无自动清理。
- 测试区参考 CP Editor：直接编辑输入与预期输出、查看只读实际输出；每例可运行或删除，侧栏可添加测试。“比较预期输出：关”表示只运行观察；开启时空文本仍是要比较的答案。
- 测试和配置是文档附属信息，修改会显示未保存状态，随文档保存、另存为和正常退出草稿恢复。表单和测试框使用普通文本输入模式，复用底层文字引擎的输入法、选区、剪贴板和撤销能力，去掉行号、补全与代码编辑界面。
- checker 支持严格文本、忽略空白 token、浮点比较。浮点 token 必须有限，满足绝对误差或相对误差条件；非数值 token 按文本比较，token 数量必须相同。
- 默认编译超时 30 秒，单例 2 秒，stdout 与 stderr 合计 1 MiB 上限；均可配置。运行器通过轮询检查超时、取消及输出量；macOS 会结束本次进程组。输出显示截断会说明，完整内容留在执行目录。
- 修改代码、测试或配置后，旧结果明确标记为旧版本，不显示为当前版本通过。每份文档同时只执行一个编译／测试作业，交互终端启动完成后可以再次运行，旧终端继续独立运行。

独立人工验收应用：`target/Altaed Runner.app`，会话为 `.cache/native-runner-session`。其中的倍增程序与两组样例是测试数据。常规 altaed 启动入口使用同一份最新构建，但不注入示例。

验证：10 项测试通过，含真实 C++ 编译、未保存编译、本地头文件、独立产物、单例／全部测试、错误答案、无预期输出、空预期输出、运行错误、超时、输出超限、取消与界面编辑隔离；fmt、Clippy 和构建通过。原生 UI 已运行两组真实样例并显示实际输出。系统终端启动路径已实现，当前自动化工具禁止访问 Terminal，终端内交互、多终端独立性需要用户亲自验收。当前只实现 macOS 终端适配，Windows MinGW-w64 打包与进程树管理仍需后续适配。

## 2026-11-02 测试侧栏修订

按用户反馈，先制作 `prototypes/test-panel/` 的布局原型，再在 GPUI 复现。右侧借鉴 CP Editor 官方界面的分区：运行信息在上、测试用例在下，内部横向分隔条可拖拽。用例数据为输入／只读实际输出／预期输出三列，测试区独立滚动。运行会显示右侧运行信息，详细输出仍可用 Cmd-J 查看。常规按钮改为透明样式，去掉灰色 hover 背景块。

修复普通文本输入模式仅有 Shift-Enter 而没有 Enter 的绑定，使用键盘事件回归确认 Enter 插入换行；范围限定在多行字段，单行配置不受影响。

性能改动：用例列表改为 UniformList，控件按可见范围创建，离屏控件释放，保留首行测量与当前聚焦输入。实际输出按执行标识缓存，仅在结果变化时更新。根视图不再逐帧复制全部文档内容；编辑事件同步模型并使执行结果失效。另修复异步保存完成时覆盖保存期间编辑状态的问题，保留最新文本与附属信息的未保存状态。

验证：12 项测试通过，包含多行 Enter、500 用例控件数量与复用、消息分隔条拖动／重置、已有编译和持久化回归。500 例测试中初始仅创建 12 个文本框（具体数量随视口变化），这是控件规模测量，不等同于帧率或所有机器的延迟保证。源码扫描与测试记录见 `evidence/test-panel-detect.json`、`evidence/panel-tests.log`、`evidence/panel-clippy.log`、`evidence/panel-build.log`。
