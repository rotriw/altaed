# 题目模型与 Competitive Companion 导入

此入口对应此前确认的浏览器 Competitive Companion，一键接收题目与样例。VS Code CPH 的本地 `.prob` 文件读取尚未实现。

## 使用

1. 启动新版 altaed 并完成或跳过首次编译环境配置，进入 IDE。
2. 状态栏出现“导入 27121”表示监听已建立。点击该入口可以打开“软件设置 → 题目导入”，关闭服务或修改端口。
3. 在浏览器题目页面点击 Competitive Companion 按钮。导入后新建未命名代码文档，测试区出现可编辑输入和预期输出；“视图 → 题目信息”查看标题、分组、来源、题目限制和输入输出方式。
4. 正常保存源码时，题目及测试跟随文档 sidecar 保存；未保存源码时也会将导入文档写入恢复草稿。

默认 27121 在扩展已支持的端口列表中；如果被 CPH/其他工具占用，IDE 会显示未连接并在悬停提示中给出原因，不抢占端口。可改用另一个未占用的默认端口，或在扩展 Custom ports 中添加所选端口。[官方接收方式](https://github.com/jmerle/competitive-companion#custom-tools)、[默认端口](https://github.com/jmerle/competitive-companion/blob/master/src/hosts/hosts.ts)

扩展可能将题目同时发给多个已监听的工具；这里只控制 altaed 自己的接收。当前实例进入 IDE 后才启动监听，欢迎页不接收导入。

## 数据与隔离

`altaed-core::problem::Problem` 是本地题目实例，拥有独立 ProblemId；每份代码仍以 DocumentId 为身份。来源 URL、题号、标题和文件名不能用于复用可变记录。

保存标题、分组、URL、时间/内存限制、交互标记、输入输出约定、测试类型、原始样例、语言信息、批次和未识别的顶层扩展字段。零值限制表示来源没有提供有效上限，不据此限制本地运行。题目限制只展示，不自动覆盖用户的编译及执行配置。

导入的原始样例保存在题目实例中，文档测试使用独立副本。编辑/删除本地测试不修改原始样例。重复导入同 URL 创建新的 ProblemId 与 DocumentId；另存为也创建独立身份并复制信息，不共享可变题目或样例。

旧记录中的 `problem_title` / `problem_url` 继续读取与展示，新导入使用结构化模型。题目模型引入版本2，编译选项使用版本3；文件样例加入后，文档/会话存储现写入版本5，同时读取版本1至5。旧二进制拒绝新版本，避免保存时静默丢掉题目或执行设置。软件 config.json 仍使用自身的版本格式。

## 接收与恢复

服务仅绑定 IPv4/IPv6 回环地址，处理根路径上的 JSON POST。接收设有请求头、正文大小和时间限制；不支持分块/压缩请求。对带 Origin 的请求，只接受浏览器扩展来源；普通网页来源不能触发导入。

接收线程解析并校验外部 DTO，转换成领域模型，写入带版本的 `companion-inbox/<DocumentId>.json`。只有收据落盘成功才返回201；此时状态为已接收，不代表 UI 已完成打开。

UI 在后台读取收据，在保存/关闭对话框结束后再接纳新文档，写入包含导入文档的会话快照，然后清理收据。启动时也恢复未处理收据，并通过 DocumentId 跳过已存在于会话/保留草稿中的记录，覆盖“写入会话后、清理收据前”中断的情况。解析或持久化失败保留记录并报告错误，不静默删除。监听线程与文件事务不运行在 GPUI 回调中。

只保存文件输入输出约定，不按照导入文件名创建/读取任意本地文件。交互题与文件输入输出的自动样例评测暂不支持，运行器会明确拒绝这类测试；仍可正常编辑、编译并在独立终端运行。没有实现 interactor 或远程提交。

## 验证范围

本地回归覆盖 HTTP 接收与网页 Origin 拒绝、同 URL 重复导入、空预期输出、原始样例隔离、另存为、sidecar/会话恢复、旧格式迁移、收据去重与原生编辑视图接纳。

2026-11-03 本地共44项测试通过，release 编译通过。使用隔离数据目录启动原生应用，通过真实回环 HTTP 发送标注为“导入预览 · 协议样例”的测试题目，确认两组输入/预期输出、题目详情与导入状态正常显示；退出再启动后文档和样例恢复，收据已清理，没有重复创建文档。未修改用户主会话。

协议样本属于明确标注的测试数据，不是真实 OJ 抓取。浏览器扩展按钮的真实点击与用户体验仍由用户验收；自动 HTTP 请求不能代替该项验收。未 push，未运行 Windows CI，也未宣称完成 Windows 人工验收。
