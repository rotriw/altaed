# C++ 编译器与编译选项

编译器发布版本和 C++ 语言标准分别处理。首次环境验证读取所选驱动的 `--version`，使用其默认语言模式编译并执行标准库程序，再逐一探测 C++98、03、11、14、17、20、23、26 的标准选项。欢迎页只显示该驱动接受的选项，允许使用默认模式或跳过配置；不要求支持 C++20。

能力检测表示驱动接受相应模式并能解析检测源文件，不代表其完整实现该版本标准。现阶段不包含旧版驱动的实验性别名及 GNU 扩展模式；需要时仍可手写编译参数。取消、超时与输出限制沿用运行器规则。

软件设置中的 C++ 标准作为新建文档的默认值。每份文档在自己的运行配置中可以选择其他标准，已有文档不会随全局设置一起改变。新文档默认参数仅为 `-O2`，不强制语言标准。

“软件设置 → C++ 编译选项”配置新建及 Companion 导入文档的默认值；“文档运行配置 → 编译器”只修改对应代码。支持优化级别（沿用附加参数、`-O0`、`-Og`、`-O1`、`-O2`、`-O3`、`-Os`）、常用警告（`-Wall -Wextra`）、调试信息（`-g`）、AddressSanitizer 和 UndefinedBehaviorSanitizer。Sanitizer 关闭时没有额外成本；是否可用取决于所选编译器和运行库，失败会显示真实编译诊断，不自动移除检查参数。

选择优化级别只替换附加参数中的 `-O` 开关。其他勾选项在附加参数基础上加入；取消勾选不会删除用户手写的同类参数。Sanitizer 启用时还加入 `-fno-omit-frame-pointer` 以改善报告堆栈。附加参数仍是一行一个独立参数，保留宏、头文件目录、链接选项及带空格路径，无 shell 展开。

新增的 `toolchain.default_compiler_options` 与 `toolchain.default_compiler_arguments` 保存在全局 `config.json`；文档自己的 `compiler_options` 随元数据和草稿保存。新建时复制默认值，之后互不影响。旧数据缺少这些字段时保留原参数，优化级别为“沿用”。编译选项引入版本3；文件样例加入后文档/会话写入版本5，读取版本1至5；旧二进制拒绝新版本，避免丢失执行选项。

已有配置缺少 `cpp_standard` 时按默认模式读取，保留已有手写 `-std` 参数。显式选择标准时，仅在执行快照中覆盖 `-std=`／`--std=` 参数，其余参数与原始配置保持不变；选择“默认”恢复手写参数的行为。编译器与 clangd 共用 `DocumentSettings::effective_compiler_arguments()`，避免补全和实际编译使用不同标准。

本轮仅在本机完成 macOS debug/release 构建与行为回归，未 push、未生成 Windows 版本，也未重新进行 PD 测试。原生界面沿用现有欢迎页、设置页的控件和配色；新增选项的人工体验仍由用户验收。
